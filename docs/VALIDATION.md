# Проверка v0.1.0

24 сентября 2026. **PASS** — [проверенный Linux CI](https://github.com/malovnik/mattermost-voice-deepgram/actions/runs/36000557970), исходный код `cf10c8e`.

Пройдено: 16 серверных тестов (`-race`), 3 frontend unit tests, 8 Chromium-сценариев, `go vet`, упаковка и полная интеграционная проверка установленного плагина на Mattermost 10.11.0. Релиз содержит архив именно из этого CI, а не отдельную непроверенную пересборку.

- Go unit/integration harness: очередь, CAS, перезапуск, ошибки провайдера, права, принадлежность файлов, удаление источника во время обработки, ветки, безопасный текст, отсутствие ключа в браузере; запуск с race detector.
- TypeScript strict check и production bundle с React из Mattermost.
- Unit tests форматов MediaRecorder и понятных ошибок.
- Chromium: настоящий MediaRecorder с виртуальным микрофоном, WebM signature и воспроизведение, добавление File в upload callback, освобождение микрофона, отказ в разрешении, позднее разрешение после закрытия, лимит длительности, защита при смене канала, SiteURL subpath.
- Архив содержит manifest, серверные ELF Linux amd64/arm64, webapp JS и SVG. Структуру проверяет scripts/check-package.mjs, рядом SHA256SUMS.
- npm audit после обновления тестового runner: 0 известных уязвимостей.
- `govulncheck v1.8.0` после обновления SDK до 0.4.4, Go до 1.26.8 и gRPC до 1.83.2: 0 уязвимостей в вызываемом коде и импортируемых пакетах; 1 уведомление в неиспользуемой части транзитивного модуля. Это не утверждение об отсутствии любых будущих уязвимостей.

Независимое ревью Claude Opus выявило и помогло исправить: бесконечные оплачиваемые повторы при отказе публикации, CSRF в строгом режиме, отказ активации при ошибке числовой настройки, задержку репликации файлов. Для исправлений добавлены регрессионные тесты. Дополнительно проверяется принадлежность аккаунта бота плагину.

GitHub CI дополнительно устанавливает архив на чистый Mattermost 10.11.0 с PostgreSQL 16 и проверяет активацию, бота, slash command, права HTTP, config без секретов, штатную загрузку и отправку аудио, скачивание и режим без ключа. Затем полный сценарий с HTTPS-подменой Deepgram: автоматическая расшифровка, личное сообщение, ветка, дедупликация, ошибка 401 и ручное восстановление. Этот сценарий прошёл в указанном выше workflow. Реальные запросы к Deepgram не выполнялись: его hostname внутри изолированной Docker-сети указывает на локальный TLS-эмулятор.

## Что не проверено без доступа владельца

- Реальный запрос к Deepgram и точность распознавания русской речи: ключ ещё не предоставлен.
- Установка на сервер команды, его настройки, ограничения upload, версия, сеть и права.
- Настоящий микрофон и разрешения Mattermost Desktop, Safari, Firefox, iOS/Android. Совместимость контейнеров предусмотрена, браузерная автоматизация выполнена только в Chromium.
- Linux arm64: бинарник собран, выполнение в CI проверяется только на amd64.

## Приёмка после подключения

1. Установить и включить архив, проверить запись и прослушивание без ключа.
2. Указать ключ в System Console и отправить 10–20 секунд русской речи; получить ответ бота в той же ветке.
3. Повторить в личном сообщении и в существующей ветке.
4. Загрузить аудио из мобильного клиента и проверить автоматическую обработку.
5. Повторно запросить готовую расшифровку: новый ответ не должен появиться.
